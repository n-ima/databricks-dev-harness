# ADR-0013: 作業目的に合わせた開発手順の正式採用

日付: 2026-09-16 JST。状態: accepted。

## 人の決定

利用者は実装・独立検証結果と未検証範囲の説明を受け、「正式採用してよい」と明示した。操作基盤の容量不足により記録だけ未反映だったが、続いて「すべて承認するので進めてください」と指示した。正式採用を再度確認しない。新版作成・更新経路検証・main公開を進め、個別案件への適用やDatabricks操作は行わない。

## 採用内容

- 既存plan/sessionで、現在の判断、必要十分な成果と証拠、今は行わないこと、停止・再検討条件を明確にする。固定の全工程を毎回要求しない。
- UIはDatabricks Appsと本番予定の実AppKit部品・共通styleを維持し、配置相談の前に保存・認証・DB・厳密な業務計算を先行実装しない。必要最小限の画面内操作は許容する。
- 全画面の配置・動作・項目・データと未決事項は設計として保持する。一部画面だけで全画面の設計完了としない。正式UI承認・独立レビュー・安全条件は緩和しない。
- UI評価課題を初回配置、修正、残画面の設計、会話履歴なしの再開まで強化する。API・分析・AI評価・障害調査も依頼目的の範囲で止まる。

## 検証と限界

候補の全回帰は728件中726成功・失敗0・file symlink権限によるskip2件。実AppKit表示、限定Codex試行、別context再開、非UI4入力の範囲判断を実施し、独立レビューの2指摘は解消した。正本は[実行記録](../../../work/evidence/2026-09-16-purpose-driven-delivery.md)と[独立レビュー](../../../work/reviews/2026-09-16-purpose-independent.md)。

実Claude Code/Copilotの反復比較、速度・token・費用の改善率、全状態の正式UI受入、実Databricksは未検証である。1時間超の実案件traceは取得しておらず直接原因は未特定。「世界最高」や無欠陥の証明とはしない。採用はこの限定を踏まえた手順改善の判断であり、未実行を成功に変更しない。

## 公開と移行

互換性を保持する手順修正として0.7.1を発行する。承認schema、CLI、権限、DBは変更しない。既存案件のUI・設計・承認・本実装を再初期化や自動削除せず、更新時に未確定の配置から新手順を適用する。案件所有の標準やtemplateから既に作った文書は自動置換しない。正式採用・stamp・GitHub到達・案件適用を別々に記録する。
