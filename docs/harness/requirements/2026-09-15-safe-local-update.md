# ローカル更新の安全な標準入口

## 目的と合意した範囲

利用者が「案件固有は保持」と毎回指示しなくても、案件を壊さずハーネスだけを更新できる入口を作る。2026-09-15に[ADR-0011](../decisions/ADR-0011-safe-local-update-adoption.md)で正式採用。受入条件SU-01〜05は候補から変更しない。既存0.4/0.5の初回更新手順は残す。個別案件への適用、Databricks操作、未採用の承認scope機能は対象外。GitHub公開は[公開要件](2026-09-15-safe-update-publication.md)として別に検証する。

利用者は対象案件のチャットで、信頼するローカル更新元フォルダーを指定する。取得はcloneでもZIP展開でもよい。人が判断するのは更新元の信頼性、競合の意味、手動移行、適用する計画。保護のための追加文言やforce回避の知識を要求しない。

## 受入条件

- [ ] SU-01: 元版を持つ案件で、配布フォルダーと版固定済みソースフォルダー（Gitなしを含む）から、同じ変更計画を作れる。計画だけでは管理ファイルを変更しない。
- [ ] SU-02: 保持指定なしでも案件コード、要件、設計、作業記録、秘密情報、依存設定はbyte単位で保持される。管理ファイルの独自変更・削除・未知の衝突は全体適用前に停止する。
- [ ] SU-03: 不明な元版、誤った対象、改変された配布物、危険なpath、未知のCLI引数、適用承認なし、計画後の変更を拒否する。起動するCLIは利用者が信頼する版を用い、そのCLIが指定source内のコードやmigration scriptを動的に実行しない。
- [ ] SU-04: 適用前バックアップと中断記録を維持し、適用後の全管理ファイルhashを照合してから導入済み版を記録する。自動rollbackや案件受入完了とは表現しない。
- [ ] SU-05: Claude Code / Copilot共通の短い自然言語入口、旧版からの移行、停止・復旧手順を日本語で提供する。独立レビューと隔離試験を残し、実provider・実案件試験と区別する。

## 制約と未確認

Node.js 22以上。ネットワーク不要の更新と、AI/Databricks利用時の通信を区別する。hashは整合性の証拠であり発行者の認証ではない。同一OS権限の敵対的な同時書込みや、任意コマンドでの保護回避を防ぐOS sandboxではない。正式採用は全環境での動作保証や実案件の受入を意味しない。
