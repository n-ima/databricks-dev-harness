# UI設計を実装対象に一致させる

2026-09-15の利用者指示が根拠。画面を作る場合は設計時点からDatabricks Appsを既定とし、別の画面基盤からDatabricksへ接続する構成は明示選択時だけとする。単独HTMLと本実装の外観が変わることを未記録のままUI確認済みにしてはいけない。

## 受入条件

- UIF-01: 本実装だけでなくUI設計・生成計画・両providerの指示が同じ既定実装先を持ち、既存モックの再利用を優先する。非UI案件へUIを追加しない。
- UIF-02: UI確認契約で実装先、採用部品/依存版、ソース/スタイル/fixture、画面・状態、独立レビューを対応付ける。未選択の外部hostingや未承認の技術例外を認定しない。
- UIF-03: UI承認入口とその利用側で契約欠落、単独の近似HTML、未解決差分、参照変更、レビューの不一致を拒否する。HTMLの拡張子だけで否定せず、同じ実装からの描画である証拠を確認する。
- UIF-04: 回帰試験で旧動作の不足を再現し、正常・拒否・例外・既存案件の移行を検証する。新contextの独立レビューを行い、実provider・実案件・実Databricksを未実施なら成功と報告しない。

## 境界

これはハーネス改善であり、添付の個別案件や実DBは変更しない。添付は別agentの説明の証拠であって、AppKit API仕様の証明ではない。既存の未採用HARD-03、公開版0.6.1とそれ以前の配布bytesを保持する。今回の依頼からpush・配備・新しい外部実行権限は推定しない。

利用者は既定方針と修正を指示している。承認検証の強化はローカル候補として独立レビューし、既存案件へ自動適用せず正式採用の判断を別に示す。
