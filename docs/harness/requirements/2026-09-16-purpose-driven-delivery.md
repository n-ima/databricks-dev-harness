# 作業の目的に合った開発・確認の進め方

## 目的と範囲

利用者の2026-09-16の実行指示を根拠に、調査、設計、改善候補の実装と検証を行う。問題は時間だけでなく、配置の相談に本実装や最終受入の作業を先取りすること。既存の正式承認・権限・配布保護を弱めず、現在の問いに必要な作業を行う。

UIだけでなく、API、データ処理、分析、AI評価、運用を対象に手順を点検する。全画面の設計、動作仕様とデータ定義の保存、Databricks Apps/実AppKit部品の既定、日本語の人向け説明を維持する。ハーネスはローカル/GitHub/CI用であり、Databricksへ配備しない。

## 対象外・未確認

案件の1時間超の実行ログは未取得で、直接原因は未特定。案件の改変、実データ・実DB操作、依存の一括更新、新たな自動配備は行わない。「世界最高」「無欠陥」はこの変更の試験から認定できない。実provider試験、公開・案件反映は、その実行条件と結果を別に記録し、ローカル試験で代用しない。

## 受入条件

- PDD-01: 出典、現行実装の根拠、反証、採用/不採用理由、未検証を分けた調査・設計記録がある。
- PDD-02: 現在の判断目的、必要十分な成果、今は行わない作業、終了/再検討条件を既存の計画・記録で扱い、固定の全工程・全帳票を一律要求しない。
- PDD-03: 全画面を一覧と動作仕様に残したまま、実AppKit部品で段階的に配置を相談できる。初回表示の条件と正式ui-mock承認の条件を区別し、backend実装や全状態の完成を初回表示へ要求しない。
- PDD-04: API契約、分析、AI評価、障害調査と小さな技術検証について、依頼した成果で止まる手順と、実環境の証明が必要になる境界が明確である。
- PDD-05: 既存の承認・証拠・権限保護を回帰試験し、別contextで手順の反例と実際の実部品表示を確認する。未実行試験を成功としない。
- PDD-06: Claude Code/Copilot向け配布スキルを同期し、既存案件の破壊や初期化のやり直しを伴わない移行手順と、実provider比較の未実行/実行結果を残す。

## 採用と配布の境界

2026-09-16、利用者の「正式採用してよい」で上記の内容と評価課題の強化を正式採用した。続く「すべて承認するので進めてください」に基づき、採用記録の確定と新版公開を進める。採用判断は解消済みで再要求しない。実装者が独立確認を代行せず、実装・検証、正式採用、配布・公開、案件への適用を区別する。[ADR-0013](../decisions/ADR-0013-purpose-driven-delivery-adoption.md)を参照。
