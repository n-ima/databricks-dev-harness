# Investigate work

1. Read the related requirement, design, runbook, active session, and recent evidence.
2. Establish a reproducible symptom and baseline before changing anything.
3. Prefer read-only inspection. Do not implement a fix unless the request includes fixing it.
4. Separate observed facts, hypotheses, tests, and conclusions.
5. Record root cause, affected scope, reproduction, and safe options in the session.
6. Promote a stable operational finding to `docs/product/knowledge/`; use `docs/harness/knowledge/` only when it generalizes across projects.
